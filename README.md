# 💧 @nemzilla/hydrate

Deterministic, event-sourced context harness for AI-assisted engineering (**HydrateZ**).

Hydrate scaffolds a disciplined workflow around a **Triad**:

| Role | Who | Responsibility |
|---|---|---|
| Product Owner | You | Scope, acceptance criteria, trade-offs, commits |
| Lead Architect | Gemini (or any chat LLM) | System design, writes the UOW spec |
| Lead Developer | Claude Code | Surgical edits, tests, journaling, commits |

Work is broken into **Units of Work (UOWs)** — self-contained task specs passed between the Architect and the Developer via the clipboard, tracked on disk so every session can pick up exactly where the last one left off.

## Install

```bash
npm install -g @nemzilla/hydrate
```

This installs two equivalent binaries: `hydrate` and `hz`.

Adding it as a dev dependency to a project (`npm install -D @nemzilla/hydrate`) also auto-provisions `.claude/commands/hydrate-*.md` slash commands into that project via a postinstall hook — no `hydrate init` required just to get the slash commands.

## Quick Start

```bash
hydrate init       # 1. Scaffold CLAUDE.md + .hydrate/ journals + .claude/commands/
hydrate prompt      # 2. Load the active UOW into .hydrate/CURRENT_UOW.md
hydrate complete     # 3. Close out the UOW once every task is checked off
```

Copy the active UOW payload to your clipboard any time with `hydrate clip`.

### Greenfield bootstrap (new repo, no history)

```bash
git init
hydrate init
# edit .hydrate/ROADMAP.md — seed your project vision & milestone checklist
hydrate context --clip
# paste into the Lead Architect (Gemini) chat, have it generate UOW-01,
# then copy the generated UOW spec back to your clipboard
claude --dangerously-skip-permissions
# inside Claude Code:
/hydrate-lfg        # or: hydrate lfg --yes
```

`hydrate lfg` (also triggered by `/hydrate-lfg`) runs `hydrate checkup` and `hydrate ingest` in one shot — a single zero-touch command that reconciles session state and pulls the clipboard UOW straight into `.hydrate/CURRENT_UOW.md`.

## What gets scaffolded

```
CLAUDE.md                         # Operating rules & AI execution protocol (managed block)
.hydrate/
  CURRENT_UOW.md                  # Active execution canvas (the in-flight UOW)
  ROADMAP.md                      # Tactical roadmap & task index
  PROJECT_JOURNAL.md              # Completion checklist log
  DEV_JOURNAL.md                  # Lead Developer implementation journal
  ARCHITECT_JOURNAL.md            # Lead Architect decision journal
  archive/                        # Completed UOWs, one file per UOW-ID
.claude/commands/hydrate-*.md     # Claude Code slash commands wrapping the CLI
docs/
  ARCHITECTURE.md                 # High-level system map (regenerated by /hydrate-arch-sync)
  ARCHITECTURE_JOURNAL.md         # Architecture decision log (ADR-style)
```

`hydrate init` is idempotent — it never overwrites a file that already exists unless you pass `--force` (which only touches `CLAUDE.md` and the `.claude/commands/` templates; `.hydrate/` journals, archive, and roadmap are never reset).

## Command reference

| Command | Summary |
|---|---|
| `hydrate init [-f]` | Scaffold the harness in the current repo |
| `hydrate prompt [--architect] [-c]` | Sync the active UOW into `.hydrate/CURRENT_UOW.md` (or dump an Architect sync payload) |
| `hydrate complete [-f]` | Mark the active UOW complete, log it, archive it, reset the canvas |
| `hydrate clip` | Copy the active UOW payload to the clipboard |
| `hydrate check` | Validate archived UOWs are fully logged across the journals |
| `hydrate checkup` / `status` | Reconcile session state (dirty tree, unarchived completions, broken build) |
| `hydrate context [-c] [--depth n]` | Compile a token-dense context payload for a fresh AI session |
| `hydrate export-portfolio [-o path] [--stdout]` | Export a structured `tech-overview.json` snapshot |
| `hydrate ingest` / `paste` [-y] | Ingest a clipboard UOW payload into `.hydrate/CURRENT_UOW.md` |
| `hydrate uow [list\|last\|<id>]` | Inspect the active or any archived UOW |
| `hydrate artifacts` | Print a map of `.hydrate/` and `.claude/commands/` plus `.gitignore` guidance |
| `hydrate sync [-r] [-f] [--path dir]` | Realign command templates & `CLAUDE.md` block to the installed version |
| `hydrate update [-l]` | Upgrade the installed package and re-sync the workspace |
| `hydrate eject [-r] [--dry-run] [-f]` | Remove the Hydrate harness from a repo |
| `hydrate hook <enable\|disable\|status>` | Auto-run `hydrate init` after every `git init` |
| `hydrate completion [bash\|zsh]` | Print a shell completion script |

Run `hydrate <command> --help` for full usage, or `hydrate --help` for the guided workflow overview.

## Claude Code integration

Every scaffolded `.claude/commands/hydrate-*.md` file is a thin wrapper that shells out to the `hydrate` CLI, so the same flows work identically from a slash command (`/hydrate-checkup`) or a raw terminal (`hydrate checkup`). See `docs/ARCHITECTURE.md` for the full component map.

## Development
